# Plan 04a — daemon IPC end-to-end run

Run on 2026-11-24 (about 09:01–09:08 +07) on Ubuntu 26.04.1 LTS, kernel 7.0.0-44, GNOME Shell
50.1, Wayland, on a laptop with 4 cores and 8 logical CPUs, with `coretemp` and `cpufreq`. The run
used the release build of `statsbard` from `feature/ipc-server` at 0b1e6e4 (Tasks 1–8 committed),
built with rustc 1.100.0, from [the Plan 04a plan](../plans/2026-11-22-rust-statsbar-04a-ipc.md).

No `statsbard` was running before the run, so none was stopped or restarted. The daemon ran with a
scratch `XDG_CONFIG_HOME`, so the user's config was never written. Pages were read with the plan's
`page-client.py`, kept outside Git. Clicks were sent as dbusmenu `Event` calls over `busctl --user`,
and profiles were switched with `powerprofilesctl set`. The profile was `performance` before and
after the run.

## Commands

```bash
./scripts/check.sh
cargo audit
cargo build --release -p statsbard
cargo tree -p statsbard -e normal
(for i in $(seq 1 25); do cargo test -q -p statsbard --test ipc --test daemon_ipc || exit 1; done)
XDG_CONFIG_HOME="$CONFIG" ./target/release/statsbard &
python3 -I page-client.py cpu 15        # beside top -b -n 3 -d 1
python3 -I page-client.py memory 15     # beside free -b and /proc/pressure/memory
python3 -I page-client.py cpu 5         # second client, 3.5 s into a first
python3 -I page-client.py cpu 6 3:0.6
python3 -I page-client.py cpu 6 3:0
busctl --user call <hub> <menu> com.canonical.dbusmenu GetLayout iias -- 0 -1 0
busctl --user call <hub> <menu> com.canonical.dbusmenu Event isvu <id> clicked i 0 0
ls -l /proc/$DAEMON/fd
powerprofilesctl set power-saver
strace -f -tt -e trace=pread64,read -p $DAEMON   # refused
grep syscr /proc/$DAEMON/io                      # each second
stat -c '%a %U' "$XDG_RUNTIME_DIR/statsbar.sock"
ps -T -p $DAEMON
grep Pss /proc/$DAEMON/smaps_rollup
```

The coretemp figures came from `/sys/class/hwmon/hwmon7/temp*_input`, since `sensors` is not
installed. The menu ids changed as `ksni` renumbered after each layout change (*Show CPU* was 7,
then 22, then 38). The client counts the hello as its first line, so its "page 3" is the second
page event. The second daemon was started with another scratch `XDG_CONFIG_HOME`; it exited
before touching it. The idle Pss was taken after the page checks, not on a fresh start.

## Not seen

1. **Pressure Warning and Critical.** Both `avg10` figures were 0.00 throughout, so only Normal was
   seen live; the thresholds are covered by the PSI tests at, below and above 10.
2. **Reads 5 s apart by `strace`.** ptrace was refused, so the cadence was read off `syscr` bursts.
   `syscr` counts every read of the process, D-Bus ones included, but the bursts at 5 s steps and
   the zeros between them under power saver, against reads every second under `performance`, show
   the 5 s cadence.
3. **The panel itself.** Plan 04b; the pages were read by a script, not shown.
4. **`cargo audit` warns about three unmaintained crates,** as in Plan 03b: RUSTSEC-2026-0370
   (`zvariant` 5.15.1), RUSTSEC-2026-0371 (`zbus_names` 4.3.5) and RUSTSEC-2026-0372
   (`zvariant_derive` 5.15.1). No fixed upgrade exists.
5. **Pss grew by about 0.5 MB** over Plan 03b's 2789 kB, in a build that adds the socket server
   and the page readers. Where the growth comes from was not measured.
6. **Clicks were not made in the GNOME UI.** They were dbusmenu `Event` calls, as in Plan 03b.
