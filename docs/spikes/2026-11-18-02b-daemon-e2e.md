# Plan 02b — daemon end-to-end run

Run on 2026-11-19 on Ubuntu 26.04.1 LTS, GNOME Shell 50.1, Wayland, against the release build of
`statsbard` from [the daemon plan](../plans/2026-11-18-rust-statsbar-02b-daemon.md). The daemon ran
under `strace -f -tt -y -e trace=pread64,openat,close` with `XDG_CONFIG_HOME` set to a scratch
directory, so the user's `~/.config` was untouched.

The run took two sessions on the same day. Session 1 (morning, PID 374511) was cut short when the
machine rebooted, which killed the daemon and deleted its logs from the scratch directory. Its
figures below are the ones read off those logs during the run; the raw logs are gone. Session 2
(evening, PID 10817) ran with a fresh scratch directory.

Each periodic read runs `pread64` until one returns 0 bytes at end of file. `/proc/meminfo` takes
two calls (1671 bytes, then 0) and `/proc/stat` three (4096, about 600, then 0) on this 8-thread
machine, all within 0.2 ms.

## Deviations and gaps

- **One lost click.** The user's first untick of *Show CPU* in GNOME did not reach the daemon, and
  nothing was being recorded on the bus at the time. The same `Event` sent with `busctl` worked, and
  the next real clicks, recorded with `dbus-monitor`, also worked. The loss was not reproduced. The
  code review later found a likely cause: the hub registered with no overview rows, so the first
  refresh changed the menu layout, `ksni` renumbered every menu id, and a click carrying an old id
  is ignored without a log line. The hub now starts with `CPU —` / `Memory —` rows (see below).
  Hiding or showing a metric still changes the layout by design, so the same window exists right
  after a toggle.
- **Restart config.** The second session's `cpu = false` was written by hand, because the reboot
  deleted the file the daemon had written. The daemon writing `cpu = false` was checked in the first
  session.
- **Driven over D-Bus.** In the second session, the user ticked *Show CPU* and *Launch at login*
  in GNOME and switched the power profile in quick settings. *Quit* was sent as a dbusmenu `Event`
  with `busctl`, not clicked.
- **Screenshot.** The Desktop Screenshot portal returned code 2, so no panel image was kept. The
  panel check rests on the user's confirmation.
- **Not tested.** The panel itself with the post-review build (see below). Autostart across a
  real login. Threads are one sample; Plan 11 measures longer. `page_open` is always false until
  Plan 04. `run.rs` is covered only by this run.

## After the code review

The review changed two things after both sessions: the hub starts with placeholder rows, and
*Launch at login* refuses an executable path ending in ` (deleted)`, which is what
`/proc/self/exe` reads once the running binary has been replaced. The rebuilt release binary was
checked the same day at 21:52 (PID 32477): a copy of it in a scratch directory ran under the same
`strace` command with a fresh `XDG_CONFIG_HOME`. Every click was sent as a dbusmenu `Event`
through `busctl`, with no one watching the panel:

| Check | Observed |
|---|---|
| Hub menu ids | `GetLayout` right after registration and 3 s later gave the same ids (*Quit* = 9 both times); only the row labels changed, from `CPU —` to values. The pre-review build in session 2 had *Quit* at 25 by the end of the run. |
| Hide CPU | Item removed; `close` on `/proc/stat` 11 ms after the click and 0 reads in the next 10 s; `cpu = false` |
| Show CPU | Item back within 2 s; `cpu = true` |
| Launch at login | Entry written, `desktop-file-validate` silent, `Exec` the running binary; second click removed it |
| Replaced binary | With the running copy deleted, `/proc/PID/exe` read `… (deleted)`. A click on *Launch at login* wrote no entry and logged `cannot start … at login: the running binary was replaced; restart StatsBar first` |
| Quit | Items gone; exit code 0 |
