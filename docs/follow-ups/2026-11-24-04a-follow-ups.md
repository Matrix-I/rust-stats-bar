# Plan 04a follow-ups

Minor findings from the Plan 04a reviews that were not fixed in 04a. Pick them up in Plan 04b
or later. Items closed during 04a (the `gnome-session` protection, the accept backoff, the exact
request limit, the runtime directory check, the socket cleanup, the sticky bit, the e2e count
swap) are not listed.

## Core

- `crates/core/src/process.rs`, `display_name`: keeps Unicode format characters (`Cf`, for example
  bidi overrides). Only control characters are replaced. A process named with a right-to-left
  override can spoof its row text. Fix: also replace `Cf` characters.
- `crates/core/src/system.rs`, `Thermal::from_celsius`: `NaN` maps to `Nominal`. Unreachable today,
  since the parser yields finite values. Fix: return `Unknown` or reject non-finite input.
- `crates/core/src/memory.rs`, `MemoryBuckets::used()`: an unguarded add on values deserialized
  from the peer. A hostile or buggy daemon can overflow it. Fix: `saturating_add` or `checked_add`
  (04b, where the panel reads peer data).
- `crates/core/src/ipc.rs` and `crates/core/tests`: no test that `Event` and the nested structs ignore unknown fields
  (plan-mandated omission). Fix: add a deserialization test with an extra field at each level.
- `crates/core`, `HashMap` with `RandomState`: ranking order of ties may differ between
  runs. Harmless today. Fix: use a deterministic tie-break if output order ever becomes observable.

## Readers

- `crates/readers/src/cpu_details.rs`, `temperatures()`: one unreadable core fails the whole call, which contradicts
  the documented behavior. Fix: skip the bad core and report the rest.
- `crates/readers/src/processes.rs`, `identify`: reads `stat`, then the uid. Between the two reads
  the pid can be reused. Fix: recheck uid and `start_ticks` at kill time (04b).
- `crates/readers/src/cpu_details.rs`, `coretemp`: reads only the first device and `Package id 0`. A multi-socket
  machine is not supported. Fix: iterate all `coretemp` devices and packages.
- `crates/readers/src/cpu_details.rs`, CPU model: a missing `cpuinfo` model is re-read on every read. Fix: cache the
  result, including the absent case.
- `crates/readers/tests/processes.rs`, scan-failure test: asserts `is_err()` only, not the error kind. Fix: assert the
  kind.

## Daemon socket and IPC

- `crates/daemon/src/ipc.rs`, event queue: if a single event exceeds 64 KiB (about 1000 or more
  CPUs), the queue drops all watchers. Fix: size the queue per event or drop only the sender.
- `crates/daemon/src/ipc.rs`, lock file open: lacks `O_NOFOLLOW` and `O_NONBLOCK`. A same-uid
  FIFO or symlink at the lock path could block or redirect the open. Fix: open with both flags.
- `crates/daemon/src/ipc.rs`, `refuse_busy`: logs once per failed write, not rate-limited. Fix:
  rate-limit or log once per client. Its Busy reply is a single non-blocking write and can be
  truncated on a full buffer. Fix: accept the truncation explicitly or retry within the deadline.
- `crates/daemon/src/ipc.rs`, Ready clients: no idle timeout. A same-uid client can hold a slot
  indefinitely. Fix: add an idle timeout.
- `crates/daemon/src/ipc.rs`, Closing state: the deadline path is untested. Fix: add a test with
  a client that never reads.
- `crates/daemon/src/ipc.rs`, bind then chmod: a window exists between `bind` and `chmod 0600`
  under the process umask. The 0700 directory and the uid check cover it. Fix: set the umask
  around `bind`, or bind in a temporary path and rename.
- `crates/daemon/src/ipc.rs` (runtime directory check), `check_private`: the path check is a TOCTOU. Fix: use `openat` on
  a directory descriptor. The parent under `/run/user` is root-owned, which limits the risk.
- `crates/daemon/src/ipc.rs`, refusal message: does not say which condition failed (owner, mode).
  Fix: name the condition.
- Lock file: created with the default mode inside the 0700 directory. Fix: create it with an
  explicit mode.

## Daemon pages and app

- `crates/daemon/src/pages.rs`, Memory rows: no `start_ticks` check. The window is microseconds
  and the panel rechecks `start_ticks`. Fix: pass the check to the Memory path as CPU does.
- `crates/daemon/src/pages.rs`, unit tests: use `pid as u64` instead of `u64::from`. Fix: switch.
- `crates/daemon/src/run.rs`: after a reader failure the welcome (first page) stays stale.
  Fix: resend or mark it.
- `crates/daemon/src/run.rs`: page problem logging is untested at the daemon level, and so is
  the slow-client drop path. Fix: add end-to-end tests.
- Reader inotify warning: a private `dbus-daemon` prints the host inotify limit message during the
  daemon tests. Harmless noise. Fix: raise the limit or filter it in the harness.

## Tests

- `crates/daemon/tests/ipc_accept_failure.rs`: assumes under 1 s between phases (wall clock).
  Fix: drive the phases from a fake clock.
- Daemon tests: only mode 0o755 is tested for the directory refusal, not 0o770 or
  0o707. Fix: parameterize over the modes.
- `crates/daemon/tests/daemon_ipc.rs`, refresh test: sleeps 500 ms (the one exception to the
  no-sleep rule), with about 450 ms margin on a loaded CI machine. Fix: wait on an observable
  event instead.
- `crates/daemon/tests/daemon_ipc.rs`, scan detector: its threshold equals the process count,
  which fails in a sparse PID namespace. Fix: derive the threshold from the fixture.
- `crates/daemon/tests/daemon_ipc.rs`, fd-reopen assertion: the message overclaims (lowest-fd
  reuse). Fix: reword it.
- Not verified at all: the foreign-owner runtime directory refusal (needs root) and the socket
  cleanup when `chmod` or `Async::new` fails (cannot be forced).
- Task 5: the implementer wrote the tests after the code (RED was reproduced afterwards). Process
  note only.
