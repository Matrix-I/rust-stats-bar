# Plan 04b follow-ups

Findings from the Plan 04b whole-branch review that were not fixed in 04b. Pick them up in Plan 05
or later.

## Accepted limitation

- `crates/daemon/src/tray.rs`, hub `menu`: "Open details…" exists only in the CPU and Memory
  menus. With both items hidden (*Show CPU* and *Show Memory* off), no menu opens the panel, so
  neither page is reachable, against the reason for decision 1 ("a hidden item's page stays
  reachable"). Kept for 04b by the user's choice on 2026-11-25. Fix: an "Open details…" entry in
  the hub menu, placed so the hub's menu ids stay stable, with a test like
  `open_details_sends_its_page_and_other_items_have_none`.

## Panel

- `crates/panel/src/window.rs`, `fail`: a failed `send` drops the link but keeps the generation, so
  the reader's EOF that follows calls `fail` again and the page shows "StatsBar quit or restarted"
  instead of the write error. Fix: bump the generation in `fail`, or ignore a second `fail` once the
  link is gone.
- `crates/panel/src/window.rs`, command-line handler: a second launch's usage error is printed on
  the running instance's stderr; the launcher gets only exit code 1. Unreachable from the daemon,
  which passes fixed arguments. Fix: `ApplicationCommandLine::printerr`.
- `crates/panel/src/window.rs`, Retry: stays clickable during the up to 2 s handshake, with no
  feedback; each click starts another connection (older ones are dropped by generation). Fix: make
  Retry insensitive while connecting.
- `crates/panel/tests/link.rs`: no test of `Link::send`'s error path, `LinkError`'s `Display` texts
  (shown on the error page), or `Closed::Refused(HandshakeTimeout)`.
- `crates/panel/tests/quit.rs`, `a_reaped_process_is_gone`: if the kernel reuses the reaped pid
  before `quit` runs, the result is `Replaced`, not `Gone`. Very unlikely. Fix: accept either.
- `crates/panel/src/window.rs`: the default height (860 px) exceeds 768 px screens; the window
  manager clamps it and the content scrolls.

## Daemon

- `crates/daemon/src/run.rs`, `start`: `std::env::current_exe()?` stops the daemon from starting
  when `/proc/self/exe` cannot be read, for an optional feature. Fix: log it and run without a
  launcher.
- `crates/daemon/src/run.rs`, `Wake::CommandsClosed`: metric items now hold command senders, so
  the channel closes only once the hub and every item drop theirs. With ksni's `watcher_offline`
  returning `true`, a service ends only on shutdown or the loss of its own connection; if only the
  hub's connection ends, the daemon keeps running with items but no hub. Not observed. Fix: settle
  whether the hub's connection can end alone; if so, exit when the hub's sender is gone.
- `crates/daemon/src/launch.rs`: exited panels are reaped on the next loop turn, so a zombie can
  stay until then. Bounded by `MAX_RUNNING`.
